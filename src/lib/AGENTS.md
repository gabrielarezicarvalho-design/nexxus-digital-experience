- Non-dedicated keys use globalProviderHops in saved provider order, never owner-first; dedicated forced_provider chains retain their explicit order to preserve account isolation.
- Special timed reseller trials derive both null token ceilings and expiry from free-trial helpers; the database permits only privileged issuance for the approved reseller and locks creation, owner and expiry so ordinary limits cannot be bypassed.
- The affiliate program is retired: no routes, links, ?REF= capture or payment attribution; historical affiliate rows stay untouched.
- An unparsable provider response body must become a logged 502 with the provider recorded, never an unhandled crash that skips the request log.
- Non-streaming requests accept providers that reply with SSE chunks: rebuild one chat.completion before the invalid-body 502 check, so stream-only suppliers keep working without changing streaming passthrough.
- Reseller key issuance (paid, trial, timed trial) and plan/expiry changes are gated in the shared reseller.server generators via free-trial's canIssueResellerKeys, so panel and public API cannot diverge.
- Token-window ceilings are decided by the check_monthly_burst DB function: api_keys.burst_exempt removes the ceiling for that key; otherwise per-key api_keys.burst_token_limit/burst_window_minutes overrides win (burst_pause_minutes, when set, pauses for that full duration from the crossing request instead of until the window ends), otherwise the monthly plan default with a one-hour window (pause state on api_keys; key_hourly_burst_status is the shared read-only view for admin and client panels); both generation protocols call it through monthly-burst keyBurstLimit/keyBurstMessage so ceilings and copy cannot diverge; keys without a ceiling skip it.
- Per-key RPM and mass-dispatch throttling are decided by the check_key_rpm DB function (state on api_keys.mass_agent_*), called by both generation protocols through mass-agent-guard with its constants, so detection, reduced limit, release and copy cannot diverge; clients listed in rpm_exempt_clients skip both inside that function.
- Paid daily resets set api_keys.daily_reset_at through the service-only fulfill_daily_reset function after verified PIX; key_tokens_today counts from the later of Brasília midnight and that instant, so every enforcement and display path honors the reset without a separate counter.
- Public Status marks a failure only for outages computed by status_summary (monitor failing or every request 5xx, more than 10 consecutive minutes, any successful minute ends it); day bars and range uptime derive from those intervals via status-rules so brief or isolated errors never paint red.
- Generation protocols never relay a supplier's raw rejection: clientUpstreamError (long-conversation-notice) maps it to a clean client message (supplier credit/auth → 503, 429 → busy, 502 → compact tip only when context-guard isLongConversation502 holds, else TEMPORARY_502_MESSAGE, any other 400 → BAD_REQUEST_400_MESSAGE, useful 4xx text only when free of supplier identity), while request_logs keep the original for admin diagnostics.
- Reseller plan token ceilings are enforced by the reseller_plans_token_limit_cap DB constraint and mirrored by RESELLER_PLAN_MAX_TOKENS, so direct writes cannot exceed the largest public package. Every paid AI chat route (/api/assistente, /api/opencode-chat) verifies the caller's session server-side before calling the gateway.
- Common routing excludes providers in DEDICATED_ONLY_PROVIDERS or with provider_accounts.dedicated_only (via isDedicatedOnly); those stay active only for keys whose forced_provider names them, so a supplier can be reserved for specific clients without disabling it.
- Cache-read input tokens are discounted by cache-billing billedUsage in both generation protocols before request_logs/record_key_usage, so every limit, window and panel that sums total_tokens follows the same rate; request_logs.cache_discount_tokens keeps raw supplier usage recoverable for provider balances and router onUsage.
- Every outbound provider call, including admin health/model probes, builds its URL from provider-transport (providerRequestBase/providerChatUrl/providerModelsUrl, including per-connector chat paths); connector gateway credentials must never be sent to a supplier's own origin.
- Free AI requests get the Nexa Cloud identity system prompt when none is sent, and responses (incl. streams) rewrite the supplier brand via free-ai-identity, so the supplier never leaks and its hidden branded prompt is skipped.
- Both generation protocols pick the request model with model-resolve pickKeyModel over the key's plan-filtered names: an unknown or out-of-plan name is replaced by the nearest model the key may use (response labelled with the real model), so terminals and apps never call or fail on models outside the plan.
- Plan-exclusive models (plan-exclusive-models) are allowed only when a plan lists them explicitly (never '*' or unrestricted keys), are routed only to their owning provider even if dedicated-only, and are never a pickKeyModel substitution target, so a cheap supplier model cannot leak into other plans or answer under another name.
- Streaming attempts are peeked with stream-peek before returning when another hop exists: an SSE error or broken connection before the first content delta counts as a failed attempt and fails over, since nothing has reached the client yet.
- Streaming responses pass through stream-peek dropErrorAfterFinish: an SSE error event after finish_reason is discarded because the answer is already complete.
- Every model, Opus included, follows the saved provider priority in the common chain (no per-family reordering in globalProviderHops); dedicated chains keep their explicit order.
- Both generation protocols estimate prompt size with context-guard (plan limit via planContextLimit) before routing: only an estimate clearly above the limit (PRE_SEND_BLOCK_MARGIN) is answered at once with a 400 compact message and no supplier call, because the estimate is approximate and doubtful cases must still reach suppliers.
- Streamed Anthropic Revenda requests use first-byte-deadline: no body byte within the deadline cancels and resends the identical request once (then a 524 failed attempt), with the timer cleared at the first byte so answers already flowing are never cut; non-streamed requests are exempt because the supplier only replies when the whole answer is ready.
- DevHub Brasil combos (devhub-combos) expand into one upstream hop per listed DevHub model (same-named first, then saved order) in fetchUpstream, so any failure moves to the next model; combo hops cool down only the inner model (for COMBO_COOLDOWN_MS), never the public combo name.
- DevHub Brasil joins the common line only for Claude models (devhubServesInCommonLine), because GPT and other families are sold only from Anthropic Revenda.
- The Anthropic Messages protocol answers every context overflow (pre-send block, supplier size rejection, long-conversation 502) with HTTP 400 invalid_request_error and promptTooLongMessage (official overflow prefix plus the project's own guidance), because Claude Code only auto-compacts on that prefix; Chat Completions keeps the Portuguese guidance.
- Monthly plan cards display and check out only the live plans.price_cents (placeholder and disabled button until loaded), because preview constants go stale when admins change prices.
- Anthropic Revenda's outage combo (upstream OUTAGE_COMBO) is appended by withOutageCombo as the very last hop whenever that provider is in a chain, ignoring cooldown order, and responses from it are labelled with the combo name, never the requested model.
